# Internationalization — Vietnamese and English

Vote System localizes system-owned frontend copy in Vietnamese and English. User-generated ballots and profile bios remain exactly as authored.

## Supported locales

```text
vi  Vietnamese — default
en  English
```

The runtime uses `vi-VN` for Vietnamese formatting and `en-VN` for English formatting. The application updates `<html lang>` without remounting the product shell.

## Locale strategy

The application intentionally does not use locale-prefixed routes. One static Next.js application is wrapped by `I18nProvider`, and the active locale is React context state.

Current guest resolution is:

1. read the browser-local `vote.locale` value;
2. use it when it is exactly `vi` or `en`;
3. otherwise default to `vi`.

The language switcher writes the selection back to `vote.locale`. Storage failure is tolerated and leaves the active in-memory locale usable.

Browser-language fallback and automatic application of an authenticated profile's `preferredLocale` are tracked as the known follow-up `TON-191`. Documentation must not claim those behaviors are active until that issue is implemented.

## Catalog structure

Catalogs live at:

```text
frontend/src/shared/i18n/messages/vi.json
frontend/src/shared/i18n/messages/en.json
```

They use matching typed domains:

```text
common
auth
ballots
profile
admin
comments
notifications
errors
```

Machine-owned status, role, provider, category, avatar, locale, and error values remain stable language-neutral codes. Components translate labels at the presentation boundary.

## Formatting

Use the helpers exposed by `useI18n()`:

- `t(domain, key, variables)` for catalog copy and interpolation;
- `formatDate(...)` for dates and times;
- `formatNumber(...)` for counts and numeric values;
- `formatRelativeTime(...)` for relative timestamps.

Do not hard-code new user-facing system copy in feature components.

## Profile preference

The backend profile persists `preferredLocale` as `vi` or `en`, and auth bootstrap responses include it. At the current commit, the value is editable and durable but is not yet automatically applied to the active UI locale. See `TON-191`.

## Verification

Frontend test and build commands run the catalog verifier:

```bash
cd frontend
npm test
npm run build
```

The verifier checks that both JSON files parse, required domains exist, and Vietnamese/English key paths match. Visual QA must cover both locales when a feature introduces or materially changes user-facing copy.

## Product rules

- Localize system UI, validation, empty states, notices, errors, accessible labels, and metadata.
- Do not auto-translate user-generated ballots, bios, future comments, or messages.
- Add Vietnamese and English copy in the same PR as every new user-facing feature.
- Keep backend/domain values stable and language-neutral.
- Do not store rendered notification text when a structured type and payload can be localized at read time.
